# 性能与可维护性优化说明

## 优化目标

- 保持现有功能完整可用（含彩蛋模式、难度选择、拖拽排序、排行榜、类别筛选）
- 降低主线程竞态导致的 UI 失效风险（彩蛋往返后）
- 建立可重复的“数据/逻辑层”自动化校验（CI）

## 已实施的关键改进（摘录）

### 1) 彩蛋往返后的稳定性

- 退出彩蛋时取消延迟清空（idle/timeout）的竞态，避免“回主菜单后又被清空”
- 难度区使用首次加载模板恢复，确保结构与样式一致
- 交互采用 data-* + 事件委托，避免 DOM 重建导致事件丢失

### 2) 类别筛选链路完整打通

- 从 `NEWS_DB` 动态归纳类别，渲染为可视化 chips
- 开始游戏前按选择类别过滤题库，处理“空选择/数量不足”
- 选择结果持久化到 localStorage，刷新后仍保持

### 3) 自动化检查与持续集成

- 新增 `scripts/verify-news-db.js`：校验新闻数据字段与唯一性
- 新增 `scripts/test-helpers.js`：校验工具函数基础行为
- 新增 GitHub Actions：push/PR 自动运行 `node scripts/ci.js`

## 如何验证

### 手动验证

- 主界面切换类别后开始游戏：只出现所选类别新闻
- 进入彩蛋模式再退出：难度按钮与类别选择保持可用、样式一致

### 自动验证（本地）

```bash
node scripts/ci.js
```

### 浏览器端回归（可选）

- `localStorage.e2e_difficulty = '1'`：自动验证难度按钮往返稳定
- `localStorage.e2e_category = '1'`：自动验证类别过滤往返稳定
